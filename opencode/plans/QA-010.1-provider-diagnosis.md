## Findings

### 1. Root Cause: Why `master_games.provider` is NULL

**Cause**: `master_games` were created from **static JSON files** (`nflSchedule2026.json`, `nflPreseason2026.json`) via `SuperAdmin.jsx` without assigning a `provider` value.

**Evidence**:
- `SuperAdmin.jsx:46-82` loads schedule from JSON and inserts via `masterGamesApi.insertAll(games)`
- The inserted objects contain: `sport, season, phase, week, game_id, home_team, away_team, home_abbr, away_abbr, game_time`
- **NO provider field is set** during creation
- Migration `009.0` added the `provider` column but did NOT backfill existing rows
- Result: 321 master_games with `provider=NULL`, `external_game_id=NULL`, `mapping_status='unmapped'`

### 2. Current Flow: How master_games are Created

**Flow**:
```
SuperAdmin.jsx (UI)
    ↓
handleLoadSchedule() → reads nflSchedule2026.json / nflPreseason2026.json
    ↓
masterGamesApi.insertAll(games) → INSERT into master_games
    ↓
master_games created with provider=NULL
    ↓
useLeague.js:createLeague() → reads master_games
    ↓
leagueGamesApi.insertAll(rows) → copies to league_games
```

**Key observations**:
- `master_games` are created **manually** by platform superadmin from static JSON
- `league_games` are created by **copying** from `master_games` when a league is created
- **No provider assignment** happens at any point in this flow
- **No reconciliation** with external providers (API-Sports, ESPN) exists

### 3. Provider/Source Mapping: Does it Exist?

**Answer**: NO mapping exists between existing `master_games` and external providers.

**Evidence**:
- `apiSportsNfl.js` adapter returns `externalGameId` and `externalCompetitionId` but is NEVER called during master_games creation
- `results-sync/index.ts` Edge Function CAN create new master_games with `provider='api-sports'` (lines 116-124) but only if they don't already exist
- The Edge Function searches for existing games by `provider='api-sports' AND external_game_id` (line 104)
- Since existing games have `provider=NULL`, they are NEVER matched
- Result: Edge Function would create DUPLICATE games instead of updating existing ones

### 4. Relationship: provider → master_games → league_games

**Current state**:
```
master_games (321 rows, provider=NULL)
    ↓ (copy on league creation)
league_games (0 rows in production)
```

**Problem**: 
- `league_games` is EMPTY (0 rows) despite 36 leagues existing
- This suggests leagues were created but games were never imported, OR games were deleted
- The `master_game_id` foreign key in `league_games` points to `master_games.id`
- Without provider assignment, there's no way to reconcile with external data sources

## Next Plan Input

### SUP-004 Requirements

If SUP-004 is the next step, the PLAN should cover:

#### 1. Provider Assignment Strategy

**Option A: Backfill existing master_games**
- Query API-Sports for all games in season
- Match by: `home_team`, `away_team`, `game_time` (±1 hour tolerance)
- Update: `provider='api-sports'`, `external_game_id=<id>`, `mapping_status='mapped'`
- Pros: Reuses existing data, no duplicates
- Cons: Requires fuzzy matching (team names, times may differ)

**Option B: Create new master_games from provider**
- Let Edge Function create new games with `provider='api-sports'`
- Delete or archive old games (provider=NULL)
- Pros: Clean separation, no fuzzy matching
- Cons: Breaks existing league_games references, data loss

**Option C: Hybrid approach**
- Backfill recent games (current season)
- Archive old games (previous seasons)
- Pros: Balances continuity and cleanliness
- Cons: More complex logic

**Recommendation**: Option A (backfill) with explicit matching rules

#### 2. Reconciliation Logic

**Precedence rules**:
- Provider data wins for: `home_score`, `away_score`, `result`, `finished`, `game_time`
- Manual data wins for: Custom games (provider=NULL, game_id starts with 'manual-')
- Conflict resolution: Log conflicts, allow platform_admin override

**Matching algorithm**:
```sql
UPDATE master_games mg
SET provider = 'api-sports',
    external_game_id = api.id,
    external_competition_id = api.competition_id,
    mapping_status = 'mapped'
FROM api_sports_games api
WHERE mg.home_team = api.home_team
  AND mg.away_team = api.away_team
  AND ABS(EXTRACT(EPOCH FROM mg.game_time - api.game_time)) < 3600  -- ±1 hour
  AND mg.season = api.season
  AND mg.phase = api.phase
  AND mg.provider IS NULL
```

#### 3. Propagation to league_games

**When to propagate**:
- After reconciliation completes
- For all leagues that imported the reconciled master_games
- Only if league has `auto_update_results=true`

**How to propagate**:
```sql
UPDATE league_games lg
SET home_score = mg.home_score,
    away_score = mg.away_score,
    result = mg.result,
    finished = mg.finished
FROM master_games mg
WHERE lg.master_game_id = mg.id
  AND mg.provider = 'api-sports'
```

#### 4. Authorization

**Who can trigger reconciliation**:
- Platform superadmin (manual trigger)
- Edge Function (automatic, via cron)
- NOT league admins (they don't have UPDATE permission on master_games)

**RLS requirements**:

#### 5. Override Policies

**Manual override**:
- Platform superadmin can manually set scores via `masterGamesApi.setScoresByGameId`
- This should set `mapping_status='manual_override'` to prevent provider from overwriting
- Reconciliation should skip games with `mapping_status='manual_override'`

**Conflict detection**:
- If provider data differs from manual data, log conflict
- Platform admin can review conflicts in console
- Decision: provider wins OR manual wins OR merge (case-by-case)
